    Chapter 10

    Ephemeral messages

    Some answers belong to one user: their balance, their settings, the result of a button they pressed in a busy group. Ephemeral messages deliver exactly that, and Hermes makes them as easy as a normal send.

    One word different

    bot.Command("balance", func(c *hermes.Context) error {
    bal := lookupBalance(c)
    return c.Ephemeral(fmt.Sprintf("Your balance: %d credits", bal))
})

    c.Ephemeral targets the current sender automatically. In a private chat that is the user who messaged the bot; for a callback query it is whoever tapped the button; for an ordinary group message it is that message's sender. Replying to someone else's message does not retarget the ephemeral response. You do not compute a receiver id yourself — the context already knows who caused the update.

    The full family mirrors the ordinary send surface:

    • c.Ephemeral(text) / c.EphemeralMessage(text)
    • c.EphemeralPhoto, c.EphemeralDocument, c.EphemeralVideo, c.EphemeralAudio, c.EphemeralVoice, c.EphemeralSticker, c.EphemeralAnimation
    bot.Command("statement", func(c *hermes.Context) error {
    pdf := buildStatementPDF(c)
    return c.EphemeralDocument(pdf, "Your statement — only you can see this.")
})

    Group ergonomics, the killer use case

    The pattern ephemeral messaging was made for: a group bot that answers a personal question without polluting the group. 

    bot.CallbackPrefix("settings:", func(c *hermes.Context) error {
    return c.Ephemeral(
        "<b>Your settings</b>\nNotifications: on\nLanguage: en",
        hermes.HTML,
        hermes.WithKeyboard(hermes.Keyboard(
            hermes.Row(hermes.Button("Toggle notifications", "settings:notif")),
        )),
    )
})

    The user who tapped sees a private panel; the other forty people in the group see nothing. Before ephemeral sends, bots did this by opening a DM the user might never notice, or worse, posting semi-private data into the group and deleting it quickly. Both were bad. This is clean.

    The edit lifecycle is complete

    Ephemeral messages are not fire-and-forget. Bot API 10.3 brought the full lifecycle, and Hermes exposes typed methods for editing text, media, captions, and keyboards of ephemeral messages, plus deletion, with streamed uploads for media edits. In practice that means a settings panel like the one above can be a living panel: tap, edit in place, tap again. 

    // After toggling, update the panel the user is looking at.
_, err := c.Bot.EditEphemeralMessageText(c.Context,
    hermes.EditEphemeralMessageTextParams{
        // receiver + message reference come from the update you handled
        Text: "<b>Your settings</b>\nNotifications: off\nLanguage: en",
        // …
    })

    Filtering for ephemeral messages is one call — hermes.EphemeralMessage — so handlers that should only ever see ephemeral traffic (or never see it) are one filter away.

    Ephemeral ≠ secure

    Ephemeral messages are a privacy convenience, not an encryption boundary. The content still flows through Telegram and your bot. Never put credentials, recovery codes, or anything you'd regret in a screenshot into one. "Only you can see this" refers to the chat UI, not to the threat model.

    When not to use them

    If the answer is useful to the whole group — game scores, poll results, moderation confirmations — send normally. Ephemeral answers in a group are invisible to admins and to your own audit log unless you log them yourself. Reach for ephemeral when the content is personal; reach for a normal send when it's communal. The bots that feel right are the ones that never mix the two up.
