    Chapter 1

    Getting started

    By the end of this chapter you will have a bot that answers /start, runs on long polling, and shuts down cleanly when you press Ctrl-C.

    Prerequisites

    You need Go 1.25 or later. That is the language floor Hermes commits to, and the CI matrix tests against it explicitly. You also need a bot token. If you have never done this: open Telegram, talk to @BotFather, send /newbot, and follow the prompts. BotFather hands you a token that looks like 123456:ABC-DEF…. Treat it like a password, because it is one.

    Never hardcode the token

    Put it in an environment variable. Every sample in this book reads os.Getenv("BOT_TOKEN"). If a token ever lands in a git history, assume it is burned and revoke it with /revoke in BotFather.

    A minimal bot

    Create a folder and a module:

    mkdir mybot && cd mybot
go mod init mybot
go get github.com/sidwiskers/hermes@latest

    Then main.go:

    main.gopackage main

import (
    "context"
    "log"
    "os"
    "os/signal"

    "github.com/sidwiskers/hermes"
)

func main() {
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
    defer stop()

    bot := hermes.New(os.Getenv("BOT_TOKEN"))
    bot.Use(hermes.Recover())

    bot.Command("start", func(c *hermes.Context) error {
        return c.Send("It works.")
    })

    if err := bot.Run(ctx); err != nil {
        log.Fatal(err)
    }
}

    Run it:

    BOT_TOKEN=123456:ABC-DEF… go run .

    Open your bot in Telegram and send /start. You should get It works. back. If you get nothing, nine times out of ten the token is wrong or the process never actually started polling. Check stderr before anything else.

    What just happened

    A few things worth noticing about those twenty lines:

    • hermes.New performs no network I/O. The token is validated on the first API call, not at construction. That means startup is instant and tests can build bots freely.
    • bot.Run(ctx) starts long polling with production defaults: batches of up to 100 updates, a 50-second long-poll timeout, and exponential backoff from 250 ms to 8 s when the network misbehaves.
    • When you press Ctrl-C, the signal cancels the context, Hermes stops taking new updates, and drains the handlers already in flight before returning. No half-processed messages.
    • On the first run Hermes calls getMe to learn the bot's username (it needs it to parse /cmd@YourBot mentions in groups). If you already know the username, skip that request with hermes.WithBotUsername("mybot").

    Handler errors are your problem — in a good way

    Handlers return error. Whatever you return is delivered to the bot's error handler, which by default logs and moves on. Set your own to see everything: 

    bot := hermes.New(os.Getenv("BOT_TOKEN"),
    hermes.WithErrorHandler(func(c *hermes.Context, err error) {
        log.Printf("handler failed: %v", err)
    }),
)

    You can swap it at runtime with bot.SetErrorHandler. The swap is atomic and safe to do while updates are flowing. And because you registered hermes.Recover(), a panic inside a handler becomes a *hermes.PanicError with a full stack trace instead of a dead process.

    Construction options you will actually use

    OptionWhat it does
    WithBotUsername("name")Skips the startup getMe call.
    WithMaxConcurrentUpdates(n)Bounds how many handlers run at once. Default is GOMAXPROCS × 8, minimum 8.
    WithErrorHandler(fn)Sends asynchronous handler errors somewhere useful.
    WithRawUpdates(true)Keeps the original JSON of every update in Update.Raw. Costs one allocation per update; off by default.
    WithHTTPClient(c)Bring your own *http.Client: timeouts, proxies, tracing transports.
    WithTestEnvironment(true)Talks to Telegram's separate test datacenter instead of production.

    There are more, but those six cover almost every real deployment. The full list lives in bot.go in the repo, and it is short enough to read in one sitting.

    A slightly less trivial bot

    Commands take arguments, and Hermes hands them to you two ways: a raw string and a pre-split slice: 

    bot.Command("echo", func(c *hermes.Context) error {
    if c.Args() == "" {
        return c.Reply("Say something after /echo.")
    }
    return c.Send(c.Args())
})

bot.Command("shrug", func(c *hermes.Context) error {
    return c.Send("¯\\_(ツ)_/¯")
})

    c.Reply quotes the incoming message; c.Send posts fresh into the chat. That is the whole difference, and choosing the right one is most of what makes a bot feel polished.

    Where to next

    Polling is fine for development and for most small bots. The next chapter covers when you should move to webhooks — and when you absolutely should not bother.
