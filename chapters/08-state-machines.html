    Chapter 8

    State machines

    "What's your name? Great — what city? Almost done…" Multi-step conversations are where naive bots go to die. The fsm package keeps them as a table of transitions instead of a thicket of ifs.

    States, events, transitions

    An FSM in Hermes is generic over two types you define: the state (a small comparable type — an int enum is idiomatic) and the data (whatever the conversation has collected so far): 

    type step uint8

const (
    idle step = iota
    awaitingName
    awaitingCity
)

type signup struct {
    Name string
    City string
}

store := session.NewMemory[fsm.Snapshot[step, signup]](24 * time.Hour)
sessions := session.New(store, session.ByChatUser, session.WithNamespace("signup"))
flow := fsm.New(sessions, idle)

    The session stores fsm.Snapshot[S, D] — the current state plus the accumulated data, so a deploy-safe store (chapter 7) makes conversations survive restarts with zero extra work.

    Declaring transitions

    err := flow.Add(fsm.Rule[step, signup]{
    From:  idle,
    Event: "begin",
    To:    awaitingName,
})

    A rule says: in state From, on event Event, move to To — optionally guarded, optionally with an action that mutates the data. Rules without a valid transition fail with fsm.TransitionError wrapping fsm.ErrNoTransition, which is how you detect "user did something out of order" as a typed error instead of a string compare.

    Wiring it to routes

    The pattern that keeps handlers flat: the command fires an event, the fallback handler reads the state. This is the full flow, adapted from the repo's own stateful example: 

    main.gobot.Use(hermes.Recover(), flow.Middleware())

bot.Command("signup", flow.Then("begin", func(c *hermes.Context) error {
    return c.Send("What should I call you?")
}))

bot.OnUpdate(func(c *hermes.Context) error {
    current, err := flow.State(c)
    if err != nil {
        return err
    }
    if current != awaitingName {
        return nil
    }
    name := strings.TrimSpace(c.Text())
    if name == "" {
        return c.Send("I need an actual name — try again.")
    }
    if err := flow.Set(c, fsm.Snapshot[step, signup]{
        State: awaitingCity,
        Data:  signup{Name: name},
    }); err != nil {
        return err
    }
    return c.Send("Nice to meet you, " + name + ". Which city?")
})

    flow.Then("begin", handler) is the useful compound: fire the begin transition, then run the handler. If the transition is illegal (say the user is already mid-flow), the handler never runs and you get the transition error, which is exactly the right place to answer "you're already signing up".

    Routing by state

    There is one ordering detail worth learning early: ordinary router filters run before route middleware. The FSM session therefore is not bound yet when a normal bot.On(...) filter is evaluated. For state-driven fallback routing, read the state inside OnUpdate and dispatch from there: 

    bot.OnUpdate(func(c *hermes.Context) error {
    current, err := flow.State(c)
    if err != nil {
        return err
    }

    switch current {
    case awaitingName:
        if !hermes.TextMessage(c) {
            return nil
        }
        return collectName(c)
    case awaitingCity:
        if !hermes.TextMessage(c) {
            return nil
        }
        return collectCity(c)
    default:
        return nil
    }
})
    About flow.In

    flow.In(...) is still useful when you call it from code that is already running inside the machine middleware. Do not use it directly as a normal router filter such as bot.On(flow.In(...), handler); at that point the session has not been attached yet.

    Guards and actions

    flow.Add(fsm.Rule[step, signup]{
    From:  awaitingCity,
    Event: "finish",
    To:    idle,
    Guard: func(c *hermes.Context, s fsm.Snapshot[step, signup]) bool {
        return s.Data.Name != "" // never finish without a name
    },
    Action: func(c *hermes.Context, d *signup) error {
        d.City = strings.TrimSpace(c.Text())
        return nil
    },
})

    The guard decides whether the transition is legal right now; the action folds the latest input into the data. Keep actions small — if an action needs three API calls, fire the event from a handler that does the calls first and keeps the action as bookkeeping.

    The escape hatch every flow needs

    Users abandon conversations. Give them a way out, always: 

    bot.Command("cancel", func(c *hermes.Context) error {
    if err := flow.Reset(c); err != nil {
        return err
    }
    return c.Send("Cancelled. /signup to start over.")
})

    Reset drops the snapshot entirely. Pair it with a session TTL (chapter 7) so abandoned flows also expire on their own. The TTL is the janitor, /cancel is the door.
